# 把玻尔参考书目接入本地论文证据链

本案例使用官方Bohrium CLI 2.9.3，实际查询CrabNet和Matbench Discovery的图谱、参考文献，以及限定DOI的结论检索。共6次请求，所有回执的计费渠道均为quota，依次显示剩余999至994次；按标价预留0.30元，逐笔人民币金额未返回。没有为凑数量用完10次上限，也没有进行论文提取或模型服务调用。

## 实际得到什么

- 两篇论文均匹配到了正确DOI的元数据，但知识图谱为空；CLI返回ok=false及“paper found but knowledge graph is empty”，不是成功取得图谱。
- 两次限定DOI、scopes=conclusion的检索均无结果。不能把它扩大为任何查询都无法命中。
- 两次书目查询成功，分别返回73和45条参考文献。前一次保留了CLI默认的反向引文/摘要返回，后一次显式关闭这些无关字段。公开包不包含摘要及反向引文，原始响应在本地保留并登记SHA256。
- 对这118个返回条目，确定性标题匹配在本地原文找到101个位置：CrabNet 60/73，Matbench Discovery 41/45。其余17个尚未由此规则验证，不自动判为错误。

这里的101是标题定位条目数，不是引用准确率。标题出现不证明DOI正确、参考书目完整、模型结论正确或原文支持某项科学判断；仍须阅读锚点上下文与原PDF。匹配仅采用NFKC、大小写及非字母数字字符规范化，至少25字符，不能用短词或模型猜测补上未匹配项。

## 不花API费用复核

克隆或下载本仓库，Python3.11+标准库即可：

```sh
python tools/bohrium_bridge.py --project . --responses experiments/bohrium/recorded --out generated/bohrium-review
python -m unittest discover -s tests -p test_bohrium_bridge.py -v
```

新输出目录中包含report.json及核验报告.md。输入是6次真实响应的明确字段投影，不是完整stdout或完整Agent轨迹；投影文件及私有原始响应哈希对应见recorded/export-provenance.json。离线脚本不联网、不执行CLI、不收费，也不将缺失图谱改成成功。在线重新请求可能消耗免费池或产生费用，不能把重放当成免费在线调用。

## 从书目线索回到原文

先在[完整定位表](../experiments/bohrium/results/核验报告.md)找论文标题，取其source_id:block_id和PDF页码，再看materials/corpus对应原文块及原PDF。

CrabNet的Roost和Matbench/Automatminer文献是阅读迁移条件的候选后续材料：先确认它们在本地原文中的实际位置，再核查输入是否需要结构、划分和调参条件。平台返回的DOI只是待核验的书目元数据，不能据标题定位便宣布已核实其方法细节。

Matbench Discovery使用本仓库登记的历史PDF存档，其独立勘误仍须同时阅读；本次空图谱及书目返回没有提供更新模型排名的依据。

## 边界与实际价值

接入提供了真实书目线索、源文定位和明确的上游未覆盖状态。论文没有可用图谱时，工作台继续以登记原文和人工/AI明确区分的审阅流程处理，不编造推理节点。本案例没有获得LKM推理链，没有在科学空间网页对话里执行实验，也没有证明模型阅读效果提升；生态赋分仍由评审判断。

原论文按各自CC BY4.0授权，元数据来源为Bohrium实际返回；代码及原创说明依仓库MIT许可。PDF字节哈希匹配不等于自动证明语料与PDF文本完全一致。独立人工专家验证尚未进行。
