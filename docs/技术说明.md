# 从论文结论到可核查判断：PaperScope 的设计与复现

本项目处理一个具体问题：看到论文摘要中的“在多数基准上达到或超过现有方法”，能否据此判断该方法适合自己的新材料筛选任务？

困难不只在摘要生成。模型可能读到了正确数字，却遗漏输入信息、比较对象、划分方式或限定条件；也可能给出了真实存在的引用，但引用并不支持它写出的结论。PaperScope 围绕这些问题组织阅读，将结论与证据、条件和边界放在同一张台账中。

本文当前介绍实现与实验方法；正式对照数据另见真实运行目录及完成后的结果报告。不能从本文推定 Skill 已提高准确率。

## 为什么先限定任务

一个“帮我读懂论文”的任务无法明确比较有无 Skill。项目改为：给定原文、读者的目标场景和一个待核查判断，回答哪些部分有依据、哪些条件不匹配、哪些信息不足。

主案例采用 CrabNet 论文，面向只有化学组成信息的材料研究者，核查“跨任务表现能否支持未见化学体系筛选”。迁移案例采用 Matbench Discovery，讨论回归误差与实际发现指标的关系。异常案例从合法素材中显式删除关键比较证据，检验是否会用记忆补造缺失数值。

这三个任务是论文阅读实验；项目没有重新训练 CrabNet，也没有运行第一性原理计算。只有实际进行的操作才能写成实验事实。

## 原文、转换件与主张台账

原件记录来源、版本、许可和 SHA-256，使用 pypdf 6.10.0 转成按 PDF 页序定位的文本块。空白归一化提高引文匹配的可操作性，但保留数字、否定和单位。每个块都有 source_id 和 block_id。

转换件是辅助索引，不能取代原件。双栏阅读顺序、旋转文字、表格列关系与公式可能提取错误，因此输入仍包含完整合法 PDF。运行过程中如需看图，应保留真实查看操作。页序与印刷页码分别处理，不能把 JSON 行号冒充论文页码。

输出分为三个部分：

- answer.md 回答具体问题，并用主张编号关联解释。
- claims.json 保存每个主张的事实/推断/未知分类、判断状态、连续原文引用及理由。
- comparison.csv 对照论文条件与目标场景，明确相符、不符、未知或不适用。

例如，一项结果可以在论文的留出数据上成立，但对目标的新化学体系仍缺少证据。此时“论文报告了该结果”属于事实，“不能直接保证迁移效果”是基于任务差异的判断，两者需要分开表达。未找到证据也不能直接写成“作者从未研究”。

## 引用匹配与语义支持是两项检查

`tools/paperscope.py` 检查：来源与块是否存在、引文能否在目标块中唯一连续匹配、主张编号是否唯一、unknown 状态是否一致、比较表是否引用已定义的主张。

它能发现修改了数字的引文、跨段拼接、错误来源和不存在的位置，但不能判断一句话是否被证据充分支持。工具输出始终保留 `semantic_support_verified=false`，也不生成赛事分数。

语义核验另行逐项检查：主张是否扩大原文量词，是否遗漏适用条件，指标方向和单位是否正确，引用支持的究竟是原文事实还是作者推断。模型原始错误不静默修正；核查记录与原始输出同时保留。

## 为什么采用公平对照

有 Skill 的答案写得好，不代表改善由 Skill 带来。本项目使用同一个完整任务、论文材料、模型、宿主、基础工具权限和预算，唯一变化是是否加载 Skill 及随附资源。

基线同样要求准确、给依据和说明不确定性。两组 A 各有一轮 with 和一轮 without；不同运行不共享当前任务中间答案。正常复测归入 A，新论文归入 B，删减材料初测与复测归入 C。

独立会话由用户明确授权的实验子代理执行，fork_turns=none。每个子代理只获得自己的输入目录，不能读取其他答案或核查表，不能联网；原生记录用于审计实际模型、时间和操作。相同系统基础能力仍然存在，这一点与一般的独立宿主会话一致。可见模型名不等于可以锁定厂商底层快照，随机种子也未能固定；结果报告需披露这些限制。

评价不按篇幅或代码量打分。逐项核查预先定义的必要信息，记录遗漏、错误、引用支持和不确定性处理，再比较原始差异。两组小样本只能支持案例级观察，不作总体显著性声明。开发者参与评价，也不能称为独立专家盲评。

## 日志与可复现边界

实验目录保留完整实际输入与输出。公开分享的会话导出从真实原生记录按时间顺序提取，保留可见任务、模型回复及真实工具调用/返回；不包含隐藏思考或账号元数据。导出说明记录原文件哈希和省略范围，不伪装为未脱敏的完整遥测。

复现分三层：

1. 不调用模型，核对来源哈希、证据引用和评价计算。
2. 在声明的模型/宿主上，使用冻结输入重新运行，保留新的真实日志。
3. 比较关键判断与验收结果，不要求非确定模型逐字相同。

工具测试通过只说明相应代码行为符合测试，不等于第二层或第三层已经完成。

## 本地操作

在项目根目录执行：

```powershell
python tools/verify_official.py
python -m unittest discover -s tests -v
python tools/paperscope.py check-corpus materials/corpus/crabnet.json
```

对真实运行的机械检查示例：

```powershell
python tools/paperscope.py check-claims --corpus materials/corpus/crabnet.json --claims runs/R01/claims.json --comparison runs/R01/comparison.csv --out runs/R01/checks.json
```

不在失败时修改原始答案来让检查通过。若需要改进 Skill，另建版本并重新跑完整对照，原先失败保留。

## 投稿材料的取舍

Skill 投稿保留完整原件、所有尝试与真实日志，同时用官方 review 索引指出关键原文片段，适应有限评分视图。原件存在不代表评审自动读过全部附件，关键解释必须在可读报告和证据索引中能核查。

GitHub 材料按当前题面限制提取文本总量，去除环境缓存和重复副本；不能为缩小包而删掉支撑结论的反例。小红书图文则从真实案例中提炼问题、操作、原文核查和限制，配图不能冒充已发生的平台运行截图。
